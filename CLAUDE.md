# MCA: Reputation - Forge 1.20.1 Mod

## Orientation
Registration inventory and package layout live in `MODMAP.md` (generated by
`.mcmod-tools/modmap.py`). Read that instead of crawling `src/`.

## Quick Reference
- **Mod ID**: `mcareputation`
- **Package**: `dev.otectus.mcareputation`
- **MC / Loader / Java**: see `gradle.properties` (official mappings, no Parchment)
- **Network protocol version**: `"5"` (`network/ReputationNetwork.java`)
- **Save format version**: `4` (`state/ReputationSavedData.FORMAT_VERSION`); `migrateFormat()` runs each
  step in order in place, and v2->v3's enrichment half is resumable through `advanceProfileMigration()`
- **API version**: `1`, unchanged; every profile operation is additive

Version numbers live only in `gradle.properties`; `processResources` expands them into `mods.toml`
and `pack.mcmeta`. Never hard-code one elsewhere, this file included.

## Build
- `./gradlew compileJava` - compile only, the normal iteration loop
- `./gradlew build` - full build, output in `build/libs/`
- `./gradlew check` - JUnit tests (plain, loader-independent - no server, level, or registries).
  `McaReflectProbeTest` replays `McaReflect.MANIFEST` against every MCA jar in `mca_probe_versions`
  (gradle.properties; the family-wide list), each in its own class loader behind a parent that hides
  the dev MCA, so a member MCA renamed in another supported release fails here rather than on a server
- `./gradlew checkJarContents` - asserts what lands in the jar
- `./gradlew apiJar` - builds the compile-only API jar for sibling add-ons
- `./gradlew verifyApiJar` - asserts the API jar's shape

`mca_version` in `gradle.properties` is **runtimeOnly**, for `runClient`/`runServer` only. Nothing
compiles against MCA. Override it to exercise the other package root:
`./gradlew runServer -Pmca_version=7.6.20+1.20.1`

`check_mod.py MCAReputation` currently reports no missing models/lang/textures. Re-run it after adding
any registered content or new translatable keys.

## Structure
```
api, api.event, api.profile  public surface for sibling mods; keep source-compatible
compat          the ONLY package allowed to touch MCA - McaReflect resolves it by name
client          client-only; common code must never import from here
network         SimpleChannel + the five packets
profile, credit   facet/recognition/profile/credit-policy schemas, fixed-point math, frozen
                  evidence and the observer resolver; leaves below reputation/, no imports from it
reputation, state, incident, community, data, event, command, util   server-side logic
```
`OptionalClassloadTest` enforces both isolation rules above. If it fails, the import is the bug.

`reputation/ReputationPolicy` is an immutable snapshot of the policy-relevant COMMON config
(`ReputationPolicy.fromConfig()`); `reputation/ServiceContext` exposes it via `policy()` and exposes
the live clock via `now()`, both with production defaults and both overridable in
`TestServiceContext` - this is the seam that lets `reputation`/`state`/`incident` logic run in plain
JUnit with no server, level, or registries.

## Conventions
- **Registration** on the MOD bus (`McaReputationMod`, `ReputationClient`); **gameplay** on the
  FORGE bus (`ReputationGameplayEvents`, `network/ReputationFeedback`). No access transformers.
- **Config**: `ForgeConfigSpec` (COMMON + CLIENT) in `McaReputationConfig`. Always go through its
  guarded accessors - the spec can be unloaded at datagen/test time and `.get()` will throw.
- **No mixins, by policy.** The MCA screen button uses `ScreenEvent.Init.Post`, not a mixin. Do not
  add one as a shortcut.
- **Profile aging goes through `ReconciliationService` like the scalar clock.** Both channels are
  advanced only by the gate, from one policy snapshot and one evaluation time, with `INSPECT` moving
  neither. `reputation/ProfileService` is the only read path exposed to the API, commands and network;
  the fold itself is `reputation/ProfileAggregator`. `ReputationContext` is the read half of the
  transaction seam (`policy()`, `now()`, `data()`), made public so one policy snapshot and one
  evaluation time can be handed down to the profile and credit calculators instead of each of them
  re-reading the config and the clock.
- **All reconciliation goes through `reputation/ReconciliationService`; never call
  `CommunityReputationRecord.reconcile` directly.** It is the single policy-aware gate (decay
  immunity, freeze semantics, `Intent ∈ {MUTATE, QUERY, INSPECT}`) for every read or write that might
  age a ledger. A second bypass reintroduces the class of bug this gate was built to close.
- **Server stop clears server-scoped state, never authority registrations.**
  `CoreIncidentAuthorities.clearServerScoped()` runs on server stop and tells every registered
  `CoreIncidentAuthority` the world went away, but the registration itself survives into the next
  world loaded in the same JVM - companions register once per JVM from common setup, so releasing
  handles here would leave them silently unregistered in a second world.
- **MCA is resolved by name, never imported.** MCA renamed its base package `net.mca` ->
  `net.conczin.mca` in 7.7.1, which crashed 0.2.0 servers. For a future MCA move, add the root to
  `McaReflect.SUPPORTED_ROOTS`; do not narrow `mca_version_range`. `McaCompat` latches itself off
  on `LinkageError`.
- MCA: Quests / MCA: Conversations / MCA: Crime / Ultima Kingdoms are optional and never compiled
  against. `[integration]` has a switch per companion namespace (`enableQuestsIntegration`,
  `enableConversationsIntegration`, `enableCrimeIntegration`, `enableUltimaKingdomsIntegration`).
- `api/CoreIncidentExemptions` (0.6.1) is the per-incident PASS/EXEMPT registry MCA: Crime's
  `ReputationExemptionBridge` registers against; the core hooks consult it after attributing a deed to a
  player. Its feature string is `incident_exemptions_v1`.
- The api jar exports `reputation/TitleScope`, `ReputationTiers`, `ReputationTierSet` and
  `ReputationTier` as read model (MCA: Quests derives its ladder answers from them); keep them
  source-compatible like `api/`.

## Family compatibility

MCA: Reputation, MCA: Quests, MCA: Crime, MCA: Conversations and MCA: Mob Compatibility are one family of
MCA Reborn add-ons, and Ultima Kingdoms consumes their APIs. The rules below hold in every repository;
the verified companion tuple per release is kept once, in `MCAReputation/docs/FAMILY_COMPATIBILITY.md`.

- **MCA Reborn is the only mandatory dependency** (`[7.6,8)`), bound by name across its four package
  roots. Architectury is never declared mandatory: MCA 7.7 dropped it and this code names no Architectury type.
- **Companion ranges carry a lower bound only** (`[x.y,)`). Forge enforces an optional range whenever
  the mod is present, and every companion binding already probes the other mod and degrades, so an
  upper bound would only ever refuse a launch. The one exception is Townstead, which is third-party
  and read-only for us: `[0.7.5,0.9)` by decision, so its 0.8 line (the one that adds `api.v1`) can
  launch beside us while the binding stubs whatever it cannot resolve.
- **Sibling APIs are consumed through vendored, hash-pinned compile-only jars** (`libs/api/`,
  `gradle/sibling-apis.properties`, `verifySiblingApis`), never a sibling checkout's class output, so a
  clean clone builds the integrations a release ships. Each sibling has one adapter package, loaded by
  name after `ModList.isLoaded`, and a static-link test keeps its types out of everything else.
- **One MCA probe fleet** in every `gradle.properties`: `7.6.20`, `7.6.26`, `7.7.0-beta.2`,
  `7.7.1-alpha.2`, `7.7.1-beta.1`, `7.7.1-beta.2` (all `+1.20.1`), replayed by the binding probe test.
- **MCA: Reputation's capability strings are drift-checked** by every consumer at startup, and the
  `1.21.1 Ports/` NeoForge trees mirror every change made here.
