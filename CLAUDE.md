# MCA: Reputation - NeoForge 1.21.1 Mod

This is the **NeoForge 1.21.1** branch (`neoforge/1.21.1`). The Forge 1.20.1 line lives on `main` and
is the upstream: each release is ported here semantically, never cherry-picked. `NeoForgePortLintTest`
bans the Forge idioms by name, so a cherry-pick fails the suite rather than the compiler.

## Orientation
Registration inventory and package layout live in `MODMAP.md` (generated by
`.mcmod-tools/modmap.py`). Read that instead of crawling `src/`.

## Quick Reference
- **Mod ID**: `mcareputation`
- **Package**: `dev.otectus.mcareputation`
- **MC / Loader / Java**: see `gradle.properties` (Parchment parameter names, pinned there)
- **Metadata file**: `src/main/resources/META-INF/neoforge.mods.toml` (not `mods.toml`)
- **Network protocol version**: `"6"` (`network/ReputationNetwork.java`) - one ahead of the Forge
  line, which is at `"5"` for the same release; the two channels were never wire-compatible and the
  two numbers are separate lineages, not a comparison
- **Public API version**: `2` (`api/McaReputationApi.API_VERSION`) - Forge is at `1`. Version 2 exists
  because the `api.event` types extend `net.neoforged.bus.api.Event`, so a bridge compiled against
  the Forge artifact does not link here. 0.5.0 and 0.6.0 add only additive members and neither moves
  it; the companions' NeoForge branches gate on `2`.
- **Save format version**: `3` (`state/ReputationSavedData.FORMAT_VERSION`); `migrateFormat()` runs
  its steps in order from the version each upgrades, so a v1 file still goes through v1->v2 on its
  way to v3. **The same number and the same bytes as the Forge build** - a world can cross between
  the two loaders at the same format number, which is what `GoldenSavedDataCompatibilityTest` asserts
  against three checked-in Forge fixtures (format 1, 2 and 3). The format-3 file is a byte-for-byte
  copy of the Forge one and its SHA-256 is pinned in that test; never regenerate it here.

Version numbers live only in `gradle.properties`; `processResources` expands them into
`neoforge.mods.toml` and `pack.mcmeta`. Never hard-code one elsewhere, this file included.

## Build
Gradle runs on the system JDK 17; the Java 21 toolchain is provisioned by the foojay resolver. There
is deliberately no `org.gradle.java.home`.

- `.mcmod-tools/gradlew-quiet.sh <dir> compileJava` - compile only, the normal iteration loop
- `... build` - full build, output in `build/libs/`; depends on `checkJarContents` and `verifyApiJar`
- `... check` - JUnit tests through `neoForge.unitTest` (plain and loader-independent - no server,
  level, or registries)
- `... checkJarContents` - constant-pool scan over the packaged jar
- `... apiJar` / `... verifyApiJar` - the compile-only API jar for sibling add-ons, and its shape check
- `... mcaJarInfo` - prints the resolved MCA jar path and SHA-256

`mca_version` in `gradle.properties` is **runtimeOnly**, for `runClient`/`runServer` only. Nothing
compiles against MCA. `mca_jar_sha256` pins the exact artifact the reflection surface in `McaReflect`
was audited against; `McaBinaryAbiTest` checks the audited members against it.

`check_mod.py MCAReputation-neoforge` is **Forge-1.20.1-shaped** and reports ~27 false positives here
(every NeoForge import, `RegistryFriendlyByteBuf`, the `ResourceLocation` factories, the payload API,
and a missing `pack.mcmeta` that this project deliberately does not ship — `checkJarContents` asserts
its absence, because NeoForge synthesises pack metadata for mods). Its content checks (missing models,
lang keys, textures) are clean. Read past the version findings, or check the lang keys with
`data/LangParityTest` instead.

## Structure
```
api, api.event, api.profile  public surface for sibling mods; keep source-compatible
compat          the ONLY package allowed to touch MCA - McaReflect resolves it by name
client          client-only; common code must never import from here
network         CustomPacketPayload + PayloadRegistrar, and the five payloads
profile, credit the public-profile schema, fixed-point math and repeat credit (0.6.0)
reputation, state, incident, community, data, event, command, util   server-side logic
```
`OptionalClassloadTest` enforces both isolation rules above. If it fails, the import is the bug.
`DedicatedServerClassloadTest` and `ClientPacketSinkTest` enforce that nothing under `network/` names
a client type, which is what replaces Forge's `DistExecutor`.

`profile`, `credit` hold 0.6.0's public-profile layer: `profile/` is a leaf below `reputation/`
(which depends on it) and imports nothing from it - policy values arrive as parameters, which is what
keeps `VillagerProfileResolver` reachable from a plain JUnit test. `credit/` is pure arithmetic over
an authored schedule. All profile evidence is **frozen onto the accepted deed**
(`profile/IncidentProfileEvidence`): a datapack edit changes future deeds and never rewrites one a
player already did, so every bound is validated on the read path as well as the write one.

`reputation/ReputationPolicy` is an immutable snapshot of the policy-relevant COMMON config
(`ReputationPolicy.fromConfig()`); `reputation/ServiceContext` exposes it via `policy()` and exposes
the live clock via `now()`, both with production defaults and both overridable in
`TestServiceContext` - this is the seam that lets `reputation`/`state`/`incident` logic run in plain
JUnit with no server, level, or registries.

## Conventions
- **Registration** on the MOD bus, off the `IEventBus` injected into `McaReputationMod`'s constructor
  (`DeferredRegister`s, `ReputationNetwork::register`, `ReputationConfigLifecycle.register`), plus the
  nested `@EventBusSubscriber` on `ReputationClient.ModBus`. **Gameplay** on the GAME bus
  (`ReputationGameplayEvents`, `network/ReputationFeedback`, `ReputationClient`, `StandingDisplay`).
  NeoForge routes by event type rather than a `bus =` selector, so the one-class-per-bus split is a
  readability contract here, not a functional one - keep it anyway. No access transformers.
- **Config**: `ModConfigSpec` (COMMON + CLIENT) in `McaReputationConfig`, registered through the
  injected `ModContainer`. Always go through the guarded accessors - the spec can be unloaded at
  datagen/test time and `.get()` will throw a different exception than Forge's did, which is why
  `read(...)` catches `Throwable`. Every key must be listed in `ConfigParityTest` and documented in
  `CONFIG.md` in the same commit.
- **No mixins, by policy.** The MCA screen button uses `ScreenEvent.Init.Post`, not a mixin. Do not
  add one as a shortcut.
- **All reconciliation goes through `reputation/ReconciliationService`; never call
  `CommunityReputationRecord.reconcile` directly.** It is the single policy-aware gate (decay
  immunity, freeze semantics, `Intent ∈ {MUTATE, QUERY, INSPECT}`) for every read or write that might
  age a ledger. A second bypass reintroduces the class of bug this gate was built to close.
- **Server stop clears server-scoped state, never authority registrations.**
  `CoreIncidentAuthorities.clearServerScoped()` runs on server stop and tells every registered
  `CoreIncidentAuthority` the world went away, but the registration itself survives into the next
  world loaded in the same JVM - companions register once per JVM from common setup, so releasing
  handles here would leave them silently unregistered in a second world.
- **MCA is resolved by name, never imported.** MCA renamed its base package `net.mca` ->
  `net.conczin.mca` in 7.7.1, which crashed 0.2.0 servers. For a future MCA move, add the root to
  `McaReflect.SUPPORTED_ROOTS`; do not narrow `mca_version_range` - it is deliberately wider than the
  compile pin so Reputation, Quests and Conversations stay mutually installable. `McaCompat` latches
  itself off on `LinkageError`.
- **Profile aging has its own clock, and only the gate moves it.** `IncidentRecord` carries
  `profileElapsedTicks`/`lastProfileObservedGameTime` beside the scalar ones, because profiles can be
  frozen (`enableProfiles=false`) while standing keeps ageing. `state/ProfileFreezeLog` is why an
  unobserved disabled interval and an observed one produce the same answer: the global switches are
  recorded as bounded epochs at the transition, so a lazy skip cannot pay a disabled interval out as
  a catch-up burst. Never advance either clock outside `ReconciliationService`.
- **Persistence is provider-neutral.** `ReputationSavedData.save(tag, HolderLookup.Provider)` and its
  private `load` counterpart are thin 1.21.1 adapters over `savePayload`/`loadPayload`, which take no
  provider. That split is what keeps the on-disk bytes identical to the Forge build's and lets the
  Forge fixtures be read directly. Write new schema through the payload pair, never the adapter.
- MCA: Quests / MCA: Conversations / MCA: Crime are optional and never compiled against.

## Porting from `main`
1. Read the Forge release commit's per-file diff (`git diff <prev> <rel> -- <path>`) and re-express it
   here. A three-way merge against the Forge base is a reasonable starting point for a file the port
   did not restructure, but every result needs auditing - the merge cannot know that
   `FriendlyByteBuf` became `RegistryFriendlyByteBuf`.
2. Translate the idioms: `ForgeConfigSpec`->`ModConfigSpec`, `ExtraCodecs.COMPONENT`->
   `ComponentSerialization.CODEC`, `new ResourceLocation(a, b)`->`ResourceLocation.fromNamespaceAndPath`,
   `javax.annotation.Nullable`->`org.jetbrains.annotations.Nullable`,
   `net.minecraftforge.eventbus.api.Event`->`net.neoforged.bus.api.Event`,
   `MinecraftForge.EVENT_BUS`->`NeoForge.EVENT_BUS`, `@Mod.EventBusSubscriber`->`@EventBusSubscriber`,
   `SimpleChannel`->`CustomPacketPayload` + `PayloadRegistrar`, `DistExecutor`->the
   `ClientPacketHandler.Sink` seam, `NbtIo`'s `File` overloads->the `Path` ones, `NbtIo.read*` gaining
   a required `NbtAccounter`.
3. Bump `PROTOCOL_VERSION` whenever the Forge one moves. The payload registrar compares the string by
   equality and nothing else, so an unbumped version lets an older client finish the handshake and
   then mis-read a payload.
4. Preserve this branch's own work. Several things exist only here: the `enableCrimeIntegration`
   config key, `/mcareputation debug integrations`, API version `2`, and the bounded `readBoundedList`
   decode. A Forge diff that appears to delete one of them is usually an adjacency artifact.
5. Retarget `@since` tags to the version that actually shipped the member **on this branch**.

## Gotchas
- `DIAGNOSIS.md` documents two real historical sync bugs - read it before touching
  `ReputationNetwork.buildSnapshot` or `resolveSelection`.
- `IMPLEMENTATION_NOTES.md` and `docs/MCAReputation_1.21.1_NeoForge_Port_Plan.md` are
  pre-implementation and stale in places. Cross-check against `MODMAP.md`.
- The golden fixtures under `src/test/resources/fixtures/` are **evidence, not output**: they were
  written by the Forge serializer. Never regenerate them to make an assertion pass.
