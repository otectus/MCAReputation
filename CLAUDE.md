# MCA: Reputation - Forge 1.20.1 Mod

## Orientation
Registration inventory and package layout live in `MODMAP.md` (generated by
`.mcmod-tools/modmap.py`). Read that instead of crawling `src/`.

## Quick Reference
- **Mod ID**: `mcareputation`
- **Package**: `dev.otectus.mcareputation`
- **MC / Loader / Java**: see `gradle.properties` (official mappings, no Parchment)
- **Network protocol version**: `"4"` (`network/ReputationNetwork.java`)
- **Save format version**: `2` (`state/ReputationSavedData.FORMAT_VERSION`); `migrateFormat()` upgrades v1 in place

Version numbers live only in `gradle.properties`; `processResources` expands them into `mods.toml`
and `pack.mcmeta`. Never hard-code one elsewhere, this file included.

## Build
- `./gradlew compileJava` - compile only, the normal iteration loop
- `./gradlew build` - full build, output in `build/libs/`
- `./gradlew check` - JUnit tests (plain, loader-independent - no server, level, or registries)
- `./gradlew checkJarContents` - asserts what lands in the jar
- `./gradlew apiJar` - builds the compile-only API jar for sibling add-ons
- `./gradlew verifyApiJar` - asserts the API jar's shape

`mca_version` in `gradle.properties` is **runtimeOnly**, for `runClient`/`runServer` only. Nothing
compiles against MCA. Override it to exercise the other package root:
`./gradlew runServer -Pmca_version=7.6.20+1.20.1`

`check_mod.py MCAReputation` currently reports no missing models/lang/textures. Re-run it after adding
any registered content or new translatable keys.

## Structure
```
api, api.event  public surface for sibling mods; keep source-compatible
compat          the ONLY package allowed to touch MCA - McaReflect resolves it by name
client          client-only; common code must never import from here
network         SimpleChannel + the five packets
reputation, state, incident, community, data, event, command, util   server-side logic
```
`OptionalClassloadTest` enforces both isolation rules above. If it fails, the import is the bug.

`reputation/ReputationPolicy` is an immutable snapshot of the policy-relevant COMMON config
(`ReputationPolicy.fromConfig()`); `reputation/ServiceContext` exposes it via `policy()` and exposes
the live clock via `now()`, both with production defaults and both overridable in
`TestServiceContext` - this is the seam that lets `reputation`/`state`/`incident` logic run in plain
JUnit with no server, level, or registries.

## Conventions
- **Registration** on the MOD bus (`McaReputationMod`, `ReputationClient`); **gameplay** on the
  FORGE bus (`ReputationGameplayEvents`, `network/ReputationFeedback`). No access transformers.
- **Config**: `ForgeConfigSpec` (COMMON + CLIENT) in `McaReputationConfig`. Always go through its
  guarded accessors - the spec can be unloaded at datagen/test time and `.get()` will throw.
- **No mixins, by policy.** The MCA screen button uses `ScreenEvent.Init.Post`, not a mixin. Do not
  add one as a shortcut.
- **All reconciliation goes through `reputation/ReconciliationService`; never call
  `CommunityReputationRecord.reconcile` directly.** It is the single policy-aware gate (decay
  immunity, freeze semantics, `Intent ∈ {MUTATE, QUERY, INSPECT}`) for every read or write that might
  age a ledger. A second bypass reintroduces the class of bug this gate was built to close.
- **Server stop clears server-scoped state, never authority registrations.**
  `CoreIncidentAuthorities.clearServerScoped()` runs on server stop and tells every registered
  `CoreIncidentAuthority` the world went away, but the registration itself survives into the next
  world loaded in the same JVM - companions register once per JVM from common setup, so releasing
  handles here would leave them silently unregistered in a second world.
- **MCA is resolved by name, never imported.** MCA renamed its base package `net.mca` ->
  `net.conczin.mca` in 7.7.1, which crashed 0.2.0 servers. For a future MCA move, add the root to
  `McaReflect.SUPPORTED_ROOTS`; do not narrow `mca_version_range`. `McaCompat` latches itself off
  on `LinkageError`.
- MCA: Quests / MCA: Conversations are optional and never compiled against.

## Terminology
- Internal and API term is **reputation**; player-facing term is **standing**.
- Tiers: stranger, acquaintance, friend, honored, revered
  (`data/mcareputation/reputation_tiers/default.json`).

## Gotchas
- `DIAGNOSIS.md` documents two real historical sync bugs - read it before touching
  `ReputationNetwork.buildSnapshot` or `resolveSelection`.
- `IMPLEMENTATION_NOTES.md` is pre-implementation and known stale in the ways its own "Drift note"
  lists. Cross-check against `MODMAP.md`.
